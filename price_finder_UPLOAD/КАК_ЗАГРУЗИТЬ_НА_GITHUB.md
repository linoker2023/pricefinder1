# Как загрузить проект на GitHub, когда не видно «uploading an existing file»

Эта ссылка показывается **только в совершенно пустом репозитории** (без единого
коммита). Если вы успели добавить README или что-то ещё — её уже нет. Ниже три
рабочих способа, начните с первого.

---

## Способ 1: прямая ссылка на страницу загрузки (работает всегда)

Откройте в браузере, подставив свой логин и имя репозитория:

```
https://github.com/ВАШ_ЛОГИН/ИМЯ_РЕПО/upload/main
```

например `https://github.com/ivanov/pricefinder/upload/main`.

Если ответит «ветка main не найдена», попробуйте то же с `master`:

```
https://github.com/ВАШ_ЛОГИН/ИМЯ_РЕПО/upload/master
```

**То же самое через меню:** в репозитории справа сверху кнопка **Add file ▾** →
**Upload files**. (Кнопка видна, только когда вы вошли в аккаунт и у вас есть права
на запись в этот репозиторий.)

Дальше:

1. Распакуйте **`price_finder_UPLOAD.zip`** — в нём файлы лежат прямо в корне,
   без лишней вложенной папки.
2. Откройте полученную папку, включите показ скрытых элементов:
   * Windows 11: **Просмотреть → Показать → Скрытые элементы**;
   * Windows 10: вкладка **Вид** → галочка **Скрытые элементы**;
   * macOS: **Cmd + Shift + .**;
   * убедитесь, что видите папку **`.github`**.
3. Выделите всё: **Ctrl + A** (macOS: **Cmd + A**).
4. Перетащите **всё выделенное** в большое поле «Drag files here» на странице GitHub.
5. Дождитесь окончания загрузки (полоски прогресса), внизу нажмите
   **Commit changes**.

### Если в диалоге выбора файлов не видно папку `.github`

В окне загрузки файлов (там, где «Открыть») нажмите **Ctrl + Shift + G**
(в Windows и macOS) и введите путь вручную, например:

```
C:\Users\ВашеИмя\Downloads\price_finder\.github
```

Либо воспользуйтесь способом 2 — он вообще не требует загружать скрытую папку.

---

## Способ 2: создать главный файл прямо на GitHub (2 минуты, надёжнее всего)

Сборку запускает один файл — `.github/workflows/build-apk.yml`. Его не обязательно
загружать: можно создать в браузере, GitHub сам построит нужные папки.

1. В репозитории: **Add file ▾ → Create new file**.
2. В поле имени файла введите ровно так, со слэшами:

```
.github/workflows/build-apk.yml
```

   Как только вы введёте первый `/`, GitHub превратит `.github` в папку — так и
   задумано. Продолжайте вводить до конца.
3. В большое поле ниже **вставьте содержимое файла `build-apk.yml`**
   (он лежит в корне архива `price_finder_UPLOAD.zip` — я положил его туда отдельной
   копией именно для этого случая). Откройте его в блокноте → Ctrl+A → Ctrl+C →
   вставьте на GitHub.
4. Нажмите **Commit changes** (справа сверху).
5. Теперь догрузите остальные файлы проекта способом 1 — уже **без** папки `.github`
   (она уже есть в репозитории).

Проверка, что всё получилось: вкладка **Actions** → слева должен появиться пункт
**build-apk**.

## Способ 3: одной командой из Git Bash (Windows) или терминала

Установите Git для Windows (<https://git-scm.com/download/win>), откройте
**Git Bash** в папке с распакованным проектом и выполните (замените логин и имя
репозитория; репозиторий на GitHub должен быть **пустым**):

```bash
cd ~/Downloads/price_finder          # папка с распакованным проектом
git init
git add .
git commit -m "pricefinder"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/pricefinder.git
git push -u origin main
```

Git спросит логин/пароль GitHub: сейчас вместо пароля нужен **Personal Access Token**
(Settings → Developer settings → Personal access tokens → Tokens (classic) →
Generate new token, галочка `repo`).

Этот способ гарантированно переносит и папку `.github`, и все вложенности.

## После загрузки: запустить сборку APK

1. Вкладка **Actions**.
2. Если видите предупреждение «Workflows aren't being run on this fork/repository» —
   нажмите **I understand my workflows, go ahead and run them**.
3. Слева выберите **build-apk** → справа кнопка **Run workflow** → ещё раз
   **Run workflow** (зелёная).
4. Через **20–40 минут** обновите страницу, кликните по верхнему (последнему) запуску
   → блок **Artifacts** → скачайте **pricefinder-apk**.
5. Распакуйте скачанный ZIP — внутри файл `pricefinder-1.0.0-...-debug.apk`.
   Перекиньте его на телефон и установите (потребуется разрешить установку из
   неизвестных источников).

## Совсем без загрузки файлов: GitHub Codespaces

Если возиться с загрузкой не хочется, можно собрать APK в облачном Linux прямо в
браузере — но код всё равно должен лежать в репозитории (способы 1–3). Дальше:

1. В репозитории: зелёная кнопка **Code ▾ → Codespaces → Create codespace on main**.
2. В открывшемся редакторе (нижняя панель — терминал) выполните:

```bash
sudo apt update && sudo apt install -y openjdk-17-jdk autoconf automake libtool \
  libltdl-dev libffi-dev libssl-dev build-essential cmake pkg-config zlib1g-dev \
  python3-dev zip unzip
pip install buildozer "cython==0.29.36"
cp android/buildozer.spec ./buildozer.spec
buildozer android debug
```

3. Готовый APK появится в папке `bin/` — кликните по нему правой кнопкой в дереве
   файлов слева → **Download**.

Бесплатный лимит Codespaces — 60 часов в месяц, сборка занимает около часа.

## Частые ошибки

| Что видите | Что делать |
|---|---|
| Нет кнопки **Add file** / **Upload files** | Репозиторий чужой или вы не вошли в аккаунт; либо используйте прямую ссылку `/upload/main` |
| «Something went really wrong» при загрузке | Слишком много файлов за раз — грузите частями (папки `pricefinder`, `android`, `config` отдельно) |
| Ветка называется не `main`, а `master` | Используйте ссылку `/upload/master` |
| После загрузки нет вкладки **Actions** | Файл `.github/workflows/build-apk.yml` не попал в репозиторий — сделайте способ 2 |
| В **Actions** пусто, хотя файл есть | Зайдите в сам файл → проверьте, что путь именно `.github/workflows/build-apk.yml`, а не `build-apk.yml` в корне |
| Сборка покраснела | Скачайте артефакт **build-log**, пришлите мне последние 30–50 строк — поправлю настройки сборки |
